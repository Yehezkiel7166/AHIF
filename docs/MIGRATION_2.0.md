# AHIF 2.0 Migration Guide

## Supported source versions

This guide covers migration from `1.9.0`, `2.0.0-rc1`, and `2.0.0-rc2`.

## Migration requirements

1. Replace repository metadata with the 2.0 versions.
2. Preserve the canonical master-photo path.
3. Preserve all stable knowledge and adapter identifiers.
4. Adopt the stable support policy and contract freeze.
5. Retain adapter status as contract-validated experimental unless empirical evidence exists.
6. Run stable release QA and regression checks.
7. Record local provider or model capability changes separately.

## Compatibility

No canonical module is removed. Existing 2.0 release-candidate schemas remain valid. Stable 2.0 adds governance, support tiers, compatibility guarantees, release evidence, and migration documentation.

## Breaking changes

None from `2.0.0-rc2`.
