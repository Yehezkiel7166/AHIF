# LTS Release QA

| Code | Failure |
|---|---|
| AHIF-LTS-001 | Release scope or exclusions are missing. |
| AHIF-LTS-002 | Version metadata is inconsistent across canonical documents. |
| AHIF-LTS-003 | Contract inventory is incomplete or unfingerprinted. |
| AHIF-LTS-004 | A breaking change lacks a major-version migration path. |
| AHIF-LTS-005 | Deprecated behavior lacks replacement guidance or removal window. |
| AHIF-LTS-006 | Empty registry is interpreted as success. |
| AHIF-LTS-007 | Independent review is absent or performed by the author. |
| AHIF-LTS-008 | Critical repository inconsistency remains unresolved. |
| AHIF-LTS-009 | LTS status is represented as production or empirical certification. |
| AHIF-LTS-010 | Adapter support tier changes without evidence and authorization. |
| AHIF-LTS-011 | Residual risk or claim boundary is omitted. |
| AHIF-LTS-012 | Release record chain is incomplete or mutable. |

Release eligibility is blocked by any unresolved critical failure.
