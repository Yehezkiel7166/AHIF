# LTS Governance QA

| Code | Failure |
|---|---|
| AHIF-LTS-001 | Candidate release or source commit is not pinned. |
| AHIF-LTS-002 | Supported scope or exclusions are ambiguous. |
| AHIF-LTS-003 | Artifact inventory is incomplete. |
| AHIF-LTS-004 | Prior compatibility guarantees are removed or unassessed. |
| AHIF-LTS-005 | Identity authority or identity-first ordering is weakened. |
| AHIF-LTS-006 | Support period, cadence, or end conditions are undefined. |
| AHIF-LTS-007 | Breaking change is classified as maintenance or backport. |
| AHIF-LTS-008 | Backport lacks origin, tests, approval, or rollback instructions. |
| AHIF-LTS-009 | Deprecation lacks replacement, migration, or removal version. |
| AHIF-LTS-010 | Required evidence is missing but decision is not `hold`. |
| AHIF-LTS-011 | Repository validation is represented as operational proof. |
| AHIF-LTS-012 | Empty registry is interpreted as successful maintenance. |
| AHIF-LTS-013 | Event history is mutable, unordered, or not digest-linked. |
| AHIF-LTS-014 | Reviewer and authorizer independence is unverified or fabricated. |
| AHIF-LTS-015 | Adapter tier, deployment, or empirical status changes implicitly. |
| AHIF-LTS-016 | Historical claim boundaries are weakened or omitted. |
| AHIF-LTS-017 | Release metadata changed before required validation passed. |
| AHIF-LTS-018 | Unverifiable required state is marked complete instead of hold. |
