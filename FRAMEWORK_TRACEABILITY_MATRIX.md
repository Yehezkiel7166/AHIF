# AHIF Framework Traceability Matrix

## Scope and interpretation

This matrix is the Sprint 029 repository-level trace from each required module to its governing specification or contract, schema boundary, regression evidence, example or template, pipeline participation, and output. A dash means that the module does not independently serialize an artifact: its requirements are consumed through the linked downstream contract and schema. This is not an empirical model-validation record or a production-readiness claim.

The canonical execution chain is: **User Request → Context → Identity → Knowledge Graph → Decision Engine → Reasoning Engine → Prompt Compiler → Quality Assurance → Final Prompt → Model Adapter**. The canonical master photo remains the sole identity authority.

## Registration and reference closure

The four Sprint 029 audit artifacts are registered in `manifest.json`, referenced from `README.md`, and enforced by `automation.config.json`. `python3 scripts/repository_checks.py audit` checks all 22 module roots, all ten logical hand-off positions (including User Request), manifest targets, and every Markdown relative link. Historical documents remain preserved and are historical evidence rather than current normative specifications.
